# 클린 코드 7장 ― 예외 처리 

1. **예외를 사용하는 이유**

* 오류 코드를 반환하면 호출부에서 매번 if/else로 검사해야 해서 코드가 지저분해지고, 체크를 빠뜨리기 쉽다.
* 예외를 사용하면 정상 로직과 오류 처리 로직을 분리해 코드가 더 읽기 좋아진다.

2. **checked 예외 vs unchecked 예외**

* checked 예외는 메서드 시그니처에 드러나므로 호출하는 곳마다 처리·전파 코드를 강제한다.
* 시간이 흐르면 상위 계층까지 throws가 퍼지며 모듈 교체·수정이 어렵고, 캡슐화가 깨질 수 있다.
* 책에서는 라이브러리 제공자가 아닌 이상 **unchecked(Runtime) 예외** 사용을 권장한다.

3. **의미 있는 예외 사용과 메시지**

* `throw new Exception()` 같이 모호한 예외는 피하고, 도메인에 맞는 **의미 있는 예외 타입**을 정의하라.
* 예외 메시지에는 “무엇을 하다가, 어떤 값 때문에, 어떤 상황에서 실패했는지”를 담아야 디버깅이 쉽다.

4. **예외 처리 전략**

* 예외를 잡는 곳에서는 **복구 전략**(재시도, 대체 처리, 사용자 안내 등)을 명확히 하라.
* 복구할 수 없는 예외는 상위로 전달하되, 로깅과 상태 정리(리소스 반환)를 확실히 한다.
* try-catch-finally 블록 안에는 최소한의 코드만 넣어 가독성을 높인다.

5. **특수 사례 패턴(Special Case)**

* “에러 상황”을 예외로만 처리하지 말고, 빈 객체(Null Object)나 특수 값 객체를 반환해 호출부에서 예외 처리를 단순화할 수 있다.

6. **null 처리**

* null을 반환하거나 인수로 받지 않도록 설계하는 것이 최선이다.
* 불가피하다면 `Objects.requireNonNull` 등으로 초기에 방어하고, 가능한 빨리 실패하게 만들어 버그를 줄인다.
