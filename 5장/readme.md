

# 클린 코드 5장 — 형식 맞추기 (Formatting) 

## 1. 형식이 중요한 이유

코드를 읽는 사람은 컴퓨터가 아니라 **사람**이다. 클린 코드의 저자 로버트 마틴은 “좋은 형식은 의사소통”이라고 말한다. 형식(Formatting)은 단순히 보기 좋게 만드는 문제가 아니라,

* 코드의 **의도를 명확히** 전달하고
* 전체 구조를 **짧은 시간에 이해**할 수 있게 하며
* 팀 구성원 간 **협업 효율을 극대화**하고
* 유지보수 및 확장 시 **리스크를 줄이는** 핵심 요소다.

형식이 통일되지 않은 프로젝트는 코드 리뷰가 느려지고, 장애 발생 시 문제 코드를 찾기 어렵다. 반대로, 형식이 잘 정돈된 프로젝트는 코드 품질이 높고, 수정 시 부작용을 줄일 수 있다.
**결론: 좋은 형식은 생산성과 안정성을 높이는 개발 투자이다.**

---

## 2. 소스 파일의 구조 ― 신문 기사처럼

로버트 마틴은 소스 파일을 **신문 기사 구조**로 구성하라고 강조한다.

### 1) 중요한 내용부터 시작

* 상단: 클래스 개요, 상수, 공용(public) 메서드 등 **핵심 API**
* 중단: 주요 로직 흐름
* 하단: 세부 구현, private 메서드, 헬퍼 메서드

이런 구성은 독자에게 “위에서 아래로 갈수록 점점 상세한 내용이 나온다”라는 예측 가능성을 제공한다.
즉, 파일을 처음 읽는 사람도 **전체 역할을 빠르게 파악**할 수 있다.

### 2) 하나의 파일은 하나의 개념

하나의 파일이 지나치게 많은 일을 하면 의도가 흐려지고 가독성이 떨어진다.
파일 크기는 가급적 **200~500라인 내**에 유지하는 것을 추천한다.

---

## 3. 세로 형식(Vertical Formatting)

세로 배치, 즉 위·아래 배치는 코드의 논리적 구조를 나타내는 가장 중요한 형식 요소다.

### 1) 빈 줄(공백 줄)의 역할

빈 줄은 **문단 구분**이다.
글에서 단락을 나누듯, 코드에서도 의미 있는 부분은 빈 줄로 구분해야 한다.
예:

* 변수 선언부 / 생성자 / 메서드 사이
* 로직 단계별로 의미 있는 단락
* API별 기능 단위

단, 의미 없이 여러 줄을 비워 두는 것은 오히려 가독성을 해친다.

### 2) 관련된 코드끼리 모아라

클린 코드의 핵심 원칙 중 하나는 **연관성 높은 코드는 물리적으로 인접하게 배치**하는 것이다.

* private 메서드는 사용하는 public 메서드 바로 아래에 배치
* 변수 선언은 사용하는 위치 근처에 두기
* 유사 목적의 메서드는 묶어서 배치
  이를 통해 독자는 코드의 자연스러운 흐름을 따라갈 수 있다.

---

## 4. 가로 형식(Horizontal Formatting)

가로 형식은 한 줄 내부의 가독성을 관리하는 규칙이다.

### 1) 한 줄 길이

한 줄은 **대략 120자 이하**가 적당하다. 너무 긴 줄은 diff 비교, 리뷰, 모바일 확인 시 불편하다.
복잡한 조건문이나 람다가 너무 길어진다면

* 의미 있는 기준점에서 줄바꿈
* 메서드 추출로 의도를 명확히 표현
  하는 것이 좋다.

### 2) 들여쓰기(Indentation)

들여쓰기는 코드의 **구조(계층)**를 표현하는 수단이다.

* 블록 내부는 2~4칸 들여쓰기
* if/while/try 등 제어구조는 반드시 들여쓰기
* 중첩 구조는 최대한 얕게 유지
  들여쓰기가 어긋난 코드는 논리를 오해하게 만들고, 버그 발생 가능성을 높인다.

### 3) 공백(Whitespace)의 사용

공백은 코드의 논리적 단위를 시각적으로 구분해 준다.

* 연산자 주변 공백: `a + b`
* 파라미터 구분: `foo(a, b, c)`
* 제어문 공백: `if (조건)`
  적절한 공백은 코드가 명확하게 읽히도록 도와주며, 과도한 공백은 오히려 눈에 거슬린다.

## 5. 팀 컨벤션의 일관성

클린 코드에서 가장 강조하는 원칙 중 하나는 **일관성(consistency)**이다.
개발자마다 스타일이 다르더라도 팀 전체 규칙이 우선이다.

### 1) 컨벤션 문서화

스타일 가이드는 꼭 문서화해야 한다.
예:

* Google Java Style Guide
* Airbnb JavaScript Style Guide

### 2) 자동화 도구 활용

사람이 형식을 관리하는 것은 비효율적이므로 다음을 적극 활용해야 한다.

* Formatter (IDE 자동 정렬)
* Linter (ESLint, Checkstyle 등)
* Pre-commit hook
  이는 ‘형식 논쟁’을 없애고 팀 생산성을 올리는 핵심이다.

---

## 6. 가독성을 해치는 대표적 안티 패턴

* 한 파일에 여러 책임을 몰아넣기
* 여러 줄의 의미 없는 빈 줄
* 블록 들여쓰기 불일치
* 150자 이상 길어지는 한 줄
* 관련 없는 메서드들이 서로 떨어져 위치
* 조건문·람다·스트림의 지나친 중첩

이런 형식 문제는 컴파일 오류는 없지만, 유지보수와 디버깅 비용을 크게 만든다.

---

## 7. 의도를 표현하는 형식

형식의 목적은 코드를 **더 잘 읽히도록** 구성하는 것이다. 이때 중요한 질문은 다음 두 가지다.

1. “내가 이 코드를 처음 본다면 이해가 쉬울까?”
2. “수정하려는 사람이 구조를 빠르게 파악할 수 있을까?”

형식은 단순히 미적인 문제가 아니다.
**팀원 전체의 생산성과 프로젝트 안정성을 높이는 전략적 도구**다.

---

## 8. 결론

클린 코드의 형식 규칙은 개발자 개인 취향을 제한하기 위한 것이 아니라,

* 협업 효율 향상
* 코드 이해 속도 증가
* 유지보수 비용 절감
* 장애 예방
  이라는 실질적 목표를 위해 존재한다.

파일 구조는 신문 기사처럼 상위 → 하위 개념으로 배열하고, 빈 줄·들여쓰기·공백을 적절히 사용해 코드를 논리적으로 구성해야 한다.
그리고 무엇보다 중요한 것은 **팀 전체의 일관된 형식 유지**다.

형식이 정돈된 프로젝트는 자연스럽게 안정성과 품질이 높아지고,
이는 곧 “읽기 쉬운 코드 = 좋은 코드”라는 클린 코드의 핵심 철학을 구현하게 된다.
